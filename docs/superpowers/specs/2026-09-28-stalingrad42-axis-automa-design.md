# Stalingrad ’42 추축군 오토마 0.1 설계

## 목적과 범위

실물 보드를 사용하는 소련군 플레이어에게 추축군을 대신할 종이 순서도와 정적 웹 헬퍼를 제공한다. 첫 버전은 영문 규칙서 v2.1의 S1 Fall Blau 시나리오(지도 A, 1~8턴, 추축군 선행)만 지원한다. 추축군은 8턴 승리 판정까지 8VP 이상을 얻으려 한다(S1.1~S1.3). 사람은 소련군의 모든 선택을 수행하고, 추축군의 실제 헥스별 이동·전투 합법성과 주사위 결과를 실물 게임에서 확인한다.

0.1의 완료 기준은 S1의 추축군 턴을 처음부터 끝까지 막힘 없이 진행할 수 있고, 종이판과 웹판이 같은 입력·주사위 값에서 같은 지시를 내리며, 판단 근거와 테스트 기록을 남기는 것이다. 전 시나리오, 소련군 오토마, 전체 보드 자동 인식·유닛별 최적 경로 계산, Vassal 연동은 후속 범위다.

## 근거 자료와 우선순위

1. 게임 판정의 최상위 근거는 로컬 `Stal42_RULES-2025-Final_LoRes.pdf`(영문 v2.1, 2025년 4월)다. GMT 게시 PDF와 SHA-256이 동일하다. 시나리오 S1 규칙은 일반 규칙에 우선한다.
2. `Stal42_RULES-2025-Final_LoRes_KO.pdf`는 v2.0 번역본이므로 한국어 용어와 도움말에만 사용한다. 영문과 다르면 영문을 따른다. 앱의 각 판단에는 영문 규칙 번호 또는 `BOT-...` 정책 ID를 붙여 원 규칙과 오토마 선택을 구별한다.
3. `Stalingrad42_v203`의 지도·시나리오·CRT/TEC 자료는 목표 목록과 초기 배치 확인에 활용하되, 모듈 버전 2.03과 영문 규칙 v2.1 사이의 불일치를 검증한다. 참조 게임 PDF의 게임별 규칙을 Stalingrad ’42 규칙으로 가져오지 않는다.
4. 참조 설계: Erasmus는 전황 단계→전략 목표→최소 필요 병력 구성, Enemy Action: Kharkov는 포위 위험과 순차 우선순위, Enemy Action: Ardennes의 Allied Solo는 군·군단별 목표와 순서가 있는 이동 방법 및 공격 여부/전투 해결의 분리, 같은 게임의 German Solo는 예비대 배치의 위험 검사와 행동 실패 시 대체 절차, Europa Universalis 봇은 공통 선택 규칙·난이도·제한된 변동성에 사용한다. D-Day at Omaha Beach의 카드식 사격·증원은 변동성 사례로만 참고한다. 각 게임의 공격 비율·카드·승리 규칙을 Stalingrad ’42에 복사하지 않는다.

## 선택한 접근

종이판이 규칙의 사용 가능한 원본이며 웹은 동일한 정책 데이터와 분기 ID를 이용해 질문·결과·기록을 표시한다. 사람이 후보 목표의 현재 보드 상태를 입력하는 혼합 방식을 사용한다. 사람이 모든 합법 행동을 먼저 나열해야 하는 방식은 부담이 크고, 전체 지도를 디지털화하는 방식은 0.1 범위를 넘는다.

`offwork`의 `feat/stalingrad42-automa-v0.1` 브랜치에서 개발한다. 새 파일은 `web/stalingrad42/`와 해당 게임의 문서·테스트에 둔다. 기존 PoG·Combat Commander 규칙, 저장 기록, Python 엔진은 변경하지 않는다. 공개 전에는 `main`의 Pages 작업이 이 브랜치를 배포하지 않는다. 기존 사이트에 추가할 때는 게임 허브의 진입 링크만 연결하고, 새 게임은 별도 경로에서 열린다.

## 결정 절차

추축군 턴의 Initial → Movement → Combat → Recovery → Supply, 사람의 소련군 턴 완료 확인, 게임 턴의 Victory Determination을 따라간다(3.0). 초기 단계의 증원, 대체, 자원, 항공·포병 지원, 철도 관련 처리를 체크리스트로 누락 없이 안내한다. 보드에 실제로 적용한 결과를 확인한 뒤 다음 단계로 넘어간다.

이동·전투의 정책 흐름은 아래와 같다.

1. **상태 확인:** 턴, 현재 VP, 지도 A의 목표 점유·접근, 추축군 보급 상태, 위험에 놓인 병력, 가용 기갑·지원 전력, 소련군의 방어 위치를 확인한다. S1의 첫 턴 이동 제한과 1기갑군 유닛 제한을 먼저 적용한다.
2. **전략 목표:** 지도 A의 VP 목표, 동쪽·남쪽 출구, Don강 남쪽 보너스를 시나리오 목표 목록에서 평가한다(S1.3). 현재 VP와 남은 턴에 따른 승점 부족분을 계산해 목표 우선순위를 올린다. 주 목표를 담당할 추축군 편제별 목표를 기록하고, 이미 달성한 목표와 보급이 끊긴 목표는 재평가한다. 여러 편제를 한 목표에 몰아 다른 전선을 비우지 않도록 예비 병력 조건을 함께 둔다.
3. **안전 검사:** 합법 이동·공격 가능 여부를 플레이어가 확인한다(5.0, 8.0). 보급선 단절, 적 ZOC 및 결속, 포위 위험, 지나친 공격 손실을 먼저 검사한다(6~7, 9~16). 치명적인 후보는 제외하고 이유를 기록한다. 위험을 감수해야 승리 가능성이 남는 후반 예외는 별도 조건과 정책 ID로 표시한다.
4. **행동 선택:** 편제마다 보급 회복, 위험 부대 구출, 목표 점령, 공격 준비, 방어·재편의 이동 방법을 정해진 순서로 검사한다. 한 유닛은 한 이동 단계에서 한 방법만 적용하고 완료 표시를 한다. 공격 후보는 별도 적격성 검사에서 예상 CRT 열, 지원, 예상 손실을 확인한다. 그 검사를 통과한 경우에만 최소 필요 병력을 배정하고, 실제 전투는 Stalingrad ’42 규칙으로 해결한다. 보급선과 후속 방어에 필요한 병력은 남긴다. 가능한 공격이 없더라도 승점 압박이 있으면 목표에 접근하도록 지시한다.
5. **실행과 후속 처리:** 규칙상 가능한 경로와 공격 순서는 종이 규칙의 순차 동률 기준으로 고른다. 선택지가 동등하거나 거의 동등할 때만 공개 d6 결과로 변동성을 준다. 행동이 불가능해지면 다음 후보 목표·행동으로 넘어간다. 예비대나 증원을 배치할 때도 배치 헥스의 보급 가능성과 포위 위험을 확인한다. 모든 후보가 불가능하면 보급 회복·재편·방어 준비 중 규칙상 가능한 첫 행동으로 종료한다.

보드 상태를 앱이 알 수 없으므로 위험·합법성 질문은 필수 확인으로 남긴다. 확인이 빠진 후보는 추천하지 않는다. 앱은 합법성을 증명했다고 주장하지 않는다. 종이판에도 동일한 질문과 탈락 사유를 인쇄한다.

S1 전용 승점 판정에서는 일반 자동 승리 기준을 적용하지 않는다. S1.3에 따라 소련 보급원에서 고립되었지만 아직 점령하지 않은 VP 헥스, 동쪽·남쪽 출구의 기계화 병력 5스텝과 해당 도로 보급선, Don강 남쪽 보너스를 각각 확인한다. 이 조건들은 목표 후보 평가와 8턴 종료 판정에 모두 반영한다.

## 매개변수와 난이도

정책은 버전이 있는 데이터로 관리한다. 목표 가치, VP 부족분 가중치, 보급·포위 위험 허용치, 공격 최소 조건, 예비 병력 보존량, 동률 처리 범위와 단계별 우선순위를 코드와 분리한다. 각 값에는 이름·설명·적용 범위·근거 정책 ID를 둔다. 이동·전투·승리의 원 규칙 자체는 난이도로 변경하지 않는다.

입문·표준·어려움은 추축군의 목표 평가 범위, 공격 준비 기준, 지원 전력 배분, 거의 동등한 후보 중 변동 범위를 조정한다. 난이도가 높을수록 더 먼 턴의 승점과 보급 위험을 고려한다. 무료 유닛·자원·VP나 주사위 수정으로 난이도를 조정하지 않는다. 초기 값은 0.1의 실험값으로 정책 파일에 명시하고 모든 로그에 정책 버전과 난이도를 남긴다. 소련군 플레이어 승률 70%·50%·35%는 테스트 후 조정할 목표이며 0.1의 검증 완료 수치로 표시하지 않는다.

## 종이판과 웹 헬퍼

종이판은 브라우저에서 인쇄 가능한 순서도와 참조표다. 웹은 한 번에 현재 단계의 질문과 필요한 보드 확인만 제시하고, 목표·행동·선택 이유·영문 규칙 번호·정책 ID·주사위 결과를 보여준다. 사용자는 이전 단계로 돌아가 입력을 수정하거나 행동 불가능을 기록해 다음 후보로 이동할 수 있다.

웹에는 판별에 필요한 최소 상태만 저장한다: 게임 ID, 시나리오·규칙·정책 버전, 난이도, 턴·페이즈, VP, 현재 목표, 입력한 관측값, d6 값, 실행·취소 이력, 검증 메모. 전체 보드나 상대 숨은 정보를 저장할 필요는 없다. 확정된 선택은 `offwork`의 기존 원칙대로 게임 전용 OPFS JSON 파일에 기록한다. 게임별 저장 디렉터리·앱 식별자를 분리하고, 내보내기·가져오기를 제공한다. 저장이 불가능하면 성공했다고 표시하지 않으며 종이판은 독립적으로 사용할 수 있다.

## 검증과 테스트

- 영문 규칙의 S1.1~S1.3, 3.0, 5~16, 18, 21~24에 대한 정책 근거표를 만들고 시나리오 예외가 일반 규칙보다 먼저 적용되는지 확인한다.
- 첫 턴의 제한, VP 부족, 편제별 목표 충돌, 보급 단절, 포위 직전, 위험한 예비대 배치, 무리한 공격, 지원 부족, 한 유닛의 중복 이동 방지, 여러 동등한 목표, 목표 전부 불가능할 때의 대체 행동, 8턴 승리 판정 사례를 수작업 예시와 자동 테스트로 검증한다.
- 같은 입력·d6·정책 버전에 대해 인쇄 순서도와 웹 결과가 일치하는지 대조한다. 기존 두 앱의 테스트와 `offwork` 정적 사이트 빌드를 실행한다.
- 사용자의 종이 플레이 기록에 `명백한 자살수`, `목표 일관성`, `포위·보급 대응`, `공격성`, `반복성`, `역이용 가능성`을 사례별로 평가한다. 승률은 시나리오·진영·난이도·플레이어 경험을 고정해 별도로 추적한다. 재현 가능한 실패 사례부터 매개변수나 분기를 수정한다.

## 배포 경계

규칙 PDF, 지도, Vassal 이미지는 설계·검증 자료다. Pages 산출물에는 0.1 운영에 필요한 자체 작성 텍스트·표·코드만 포함하고, 원본 대형 파일을 자동 복사하지 않는다. 원본 자산을 공개 페이지에 포함할 필요가 생기면 사용 조건을 확인한 뒤 별도 결정한다. 기존 Pages 워크플로는 `main`만 배포하므로 브랜치의 테스트 결과와 사이트 산출물을 검토한 뒤 공개 경로를 연결한다.
